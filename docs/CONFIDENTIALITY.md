# Public Data & Confidentiality Boundary

This repository is a public research project. Its credibility depends on keeping public research completely separate from employment work.

## Permitted inputs

- public market data whose redistribution/use terms permit the intended use,
- public regulatory or exchange material,
- synthetic data generated specifically for the repository,
- public academic methods and model architectures with appropriate attribution,
- generic engineering patterns that are not copied from proprietary systems.

## Prohibited material

Do **not** commit or reconstruct:

- employer or customer data,
- internal database schemas, table names, column names, queries, screenshots or reports,
- internal model coefficients, parameters, thresholds, calibration outputs or monitoring results,
- proprietary business rules, approval logic, workflows or undocumented operating procedures,
- credentials, access tokens, account identifiers or private financial information,
- licensed datasets whose terms do not allow public redistribution.

## Clean-room rule

Public examples must be independently designed from public standards, public research, or synthetic data. A public implementation must not reproduce distinctive logic from a private workplace system simply by renaming variables.

## Review rule

If a contribution's provenance is uncertain, the default decision is **do not publish it** until its source and redistribution rights are clear.

## Research integrity

This boundary is separate from model validation. A model can be technically valid and still be unsuitable for public release if its inputs or implementation provenance are not clean.
